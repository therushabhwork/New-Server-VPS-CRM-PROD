## 2. Deep Dive: Root Cause Across Backend & Frontend

### 2.1. Backend Strict Isolation Root Cause
In multiple backend services, an `applyStrictIsolation` function was hardcoded to only preserve `role: 'admin'` for `keval@swatiswitchgears.com`, while forcefully overriding all other actors (including Samir Sheth) to `role: 'user'`:

1. **`server/services/quotationService.js` (lines 862-866 & 1313-1316)**:
   ```javascript
   const applyStrictIsolation = (actor) => {
     const email = String(actor?.email || '').toLowerCase().trim()
     if (email === 'keval@swatiswitchgears.com') return { ...actor, role: 'admin' }
     return { ...actor, role: 'user' }
   }
   ```
   - When Samir Sheth called `GET /api/quotations`, `applyStrictIsolation` turned their role into `'user'`.
   - `quotationService.list` filtered the query so only quotations directly created or owned by Samir Sheth were returned. All other users' quotations (and historical quotations from earlier owners) were excluded.
   - `get(actor, id)` and `search(actor, query)` also used `applyStrictIsolation`, blocking Samir Sheth from opening other users' quotations.

2. **`server/services/dealService.js` (lines 165-185)**:
   ```javascript
   customScopeBypass: (actor) => {
     return isPrivilegedRole(actor.role) || (actor.email && actor.email.toLowerCase() === 'keval@swatiswitchgears.com')
   }
   const applyStrictIsolation = (actor) => {
     const email = String(actor?.email || '').toLowerCase().trim()
     if (email === 'keval@swatiswitchgears.com') return { ...actor, role: 'admin' }
     return { ...actor, role: 'user' }
   }
   ```
   - When Samir Sheth accesses Search Deal (`/admin/deals/search`), deals were also isolated, preventing Samir Sheth from accessing deals or their associated quotation records generated by other users.

3. **`server/services/customerService.js` (lines 39-49)**:
   - Also forcefully downgraded non-Keval users via `applyStrictIsolation`.

4. **`server/repositories/dashboardRepository.js` (lines 62-68)**:
   - Counted quotation stats with strict isolation for everyone except Keval.

## 3. Privileged Admin Identity Matrix (Keval & Samir)

To guarantee resilient identification across all login methods (email, username, display name, legacy numeric ID), we implement a shared identity validator:

```javascript
const isPrivilegedQuotationAdmin = (actor) => {
  if (!actor) return false
  const email = String(actor?.email || '').toLowerCase().trim()
  const name = String(actor?.name || '').toLowerCase().trim()
  const username = String(actor?.username || '').toLowerCase().trim()
  const actorId = String(actor?.id || actor?._id || actor?.legacyId || '').trim()

  // 1. Keval V Shah
  if (
    email === 'keval@swatiswitchgears.com' ||
    name === 'keval v shah' ||
    name === 'keval shah' ||
    username === 'kevalvshah' ||
    actorId === '16'
  ) {
    return true
  }

  // 2. Samir Sheth
  if (
    email === 'samirsheth@swatiswitchgears.com' ||
    email.startsWith('samir.sheth@') ||
    email.startsWith('samirsheth@') ||
    email.startsWith('samir.seth@') ||
    email.startsWith('samirseth@') ||
    name === 'samir sheth' ||
    name === 'samir seth' ||
    username === 'samir-sheth' ||
    username === 'samirsheth' ||
    actorId === '15'
  ) {
    return true
  }

  // 3. Global Super Admin / Admin role
  if (actor.role === 'admin' || actor.role === 'super_admin') {
    return true
  }

  return false
}
```

## 4. Architectural Solutions by Surface

### 4.1. Quotation Manager (`/admin/quotation-manager/view`)
- **Backend**: In `server/services/quotationService.js`, update `applyStrictIsolation` to use `isPrivilegedQuotationAdmin(actor)`. When true, returns `{ ...actor, role: 'admin' }`.
- **List Queries**: `quotationService.list` returns `baseList` containing all quotations across all users.
- **Before / Historical Quotations**: Older quotations (`isOldQuotation: true`, `oldQuotationNumber`, `oldQuotationDate`, legacy records) will no longer be dropped or blocked by owner scoping. Both Keval V Shah and Samir Sheth will see all historical quotes in both Account and Deal tabs.
- **Attachment & View Access**: `get(actor, id)` and `viewAttachment` allow full inspection of any quotation document and revision history.

### 4.2. Search Account (`/admin/accounts/search` & `/accounts/search`)
- In Account Search, clicking an account opens [AccountDetailsDrawer.jsx](file:///c:/Users/Lumos/Desktop/New-Server-VPS-CRM-PROD/src/pages/admin/accounts/AccountDetailsDrawer.jsx).
- The action **"View Quotations"** navigates to:
  `/admin/quotation-manager/view?tab=accounts&accountNo=${accNo}&accountName=${accName}&accountId=${accId}`
- Because both Keval V Shah and Samir Sheth receive the full quotations list from the backend and `DataContext.jsx`, all quotations generated for that account across all sales reps are displayed.
- Any "before quotations" previously associated with that account will also be displayed.

### 4.3. Search Deal (`/admin/deals/search` & `/deals/search`)
- In Deal Search, opening a deal in [AdminDealDetailPage.jsx](file:///c:/Users/Lumos/Desktop/New-Server-VPS-CRM-PROD/src/pages/admin/deals/AdminDealDetailPage.jsx):
  - Clicking **"View Quotation"** navigates to:
    `/admin/quotation-manager/view?tab=deal&dealId=${deal.id}&dealNumber=${deal.dealNumber}`
  - Both Keval V Shah and Samir Sheth will see all quotations generated for that deal by any user.
  - In `server/services/dealService.js`: update `customScopeBypass` and `applyStrictIsolation` to recognize Samir Sheth so that deal access is identical to Keval V Shah.
  - In `Quotations.jsx` (inline quotation modal for deals): all deal revisions and linked quotations are fully visible.

### 4.4. Isolated Working Guarantee for Regular Users
- For all regular sales reps (e.g. `jay@swatiswitchgears.com` or users with `role: 'user'` not matching Keval or Samir):
  - `isPrivilegedQuotationAdmin(actor)` returns `false`.
  - `applyStrictIsolation` returns `{ ...actor, role: 'user' }`.
  - Scoped queries continue to strictly filter by the user's assigned ID and owner code.
  - Standard user isolation is completely preserved.
